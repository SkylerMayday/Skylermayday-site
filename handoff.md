## Changes made this session (2026-07-11)

### Card zoom
Built via `write-spec` (interactive scoping with Skyler: full-screen modal, scale existing image not a higher-res fetch, view-and-close only — no caption/prev-next/swipe-close, deliberately not parked as P1) → `dev-team-pipeline`. Architecture: `CardSlot` owns its own open/closed state and renders `CardZoomModal` via `createPortal` to `document.body` — simplest focus-restore, automatic single-open (the fixed backdrop physically blocks opening a second card). Capture-phase Esc/arrow-key handling on the modal preempts `BinderPageViewer`'s bubble-phase page-turn listener, so arrow keys can't flip the page behind an open modal. No new npm dependency (none existed in this repo before).

### Card zoom scroll-lock fix
Skyler caught this live: the modal's backdrop blocked clicks to the grid behind it but not scroll — you could still wheel/touch-scroll the page while zoomed. Root cause (via `debug` skill): nothing set `overflow: hidden` on `body` while the modal was mounted, and nothing prevented `touchmove` scroll-chaining. The original build's Planner had explicitly rejected scroll-lock to avoid the layout shift from the scrollbar disappearing — that was the actual bug: the shift needed solving, not the lock skipping. Fix: `scrollbar-gutter: stable` on `html` (permanently reserves the gutter so toggling `overflow: hidden` never shifts width) + a guarded `touchmove` listener with `{ passive: false }` and `overscroll-behavior: contain` for iOS scroll-chaining edge cases.

### Mobile swipe-to-turn-page
Native `addEventListener("touchstart"/"touchend", ..., { passive: true })` on the grid `<div>` in `BinderPageViewer.tsx` — deliberately not React synthetic `onTouchStart`/`onTouchEnd` JSX props. This is the load-bearing decision: native listeners follow the real DOM tree, and since `CardZoomModal`'s backdrop is portaled outside the grid's DOM subtree, a native grid listener structurally cannot fire for a touch landing on an open zoom modal — no guard code needed. Synthetic props would have propagated along the React tree instead and leaked the swipe through. Reuses the existing boundary-clamped `goToNext`/`goToPrev` handlers (no wrap-around, no duplicated clamp math). Desktop unchanged.

### Shelf plank height
Two direct CSS edits per Skyler's ask — `.binder-shelf`'s `border-bottom` (the wood "front lip"/support the binders visually rest against) went 14px → 29px → 50px. Treated the unit as 1:1 px, matching this design system's existing convention (no mm units anywhere in the codebase).
