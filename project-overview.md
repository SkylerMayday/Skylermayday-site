# SkylerMayday.com — Project Overview

## What This Is
Personal hub website for SkylerMayday.com — brand home, auto-pulled Twitch/YouTube content, Pokémon TCG showcase, the natively-hosted Stream Analyser, and a front door for the Pokédex Binder app. Full requirements in [docs/website-spec.md](docs/website-spec.md); the PTCG binders bookshelf redesign has its own spec at [docs/ptcg-binders-redesign-spec.md](docs/ptcg-binders-redesign-spec.md); the second-bookshelf/shelf-grouping feature has its own spec at [docs/ptcg-second-bookshelf-spec.md](docs/ptcg-second-bookshelf-spec.md).

**Live and deployed** at skylermayday.com. Code lives in a separate sibling repo: `D:\Claude Projects\skylermayday-site` (`github.com/SkylerMayday/Skylermayday-site`) — this `SkylerMaydaySite` directory is the planning/docs project (specs, handoff, gaps), not the code.

## Architecture (as actually built)
- **Stack:** Next.js 15 App Router, React 19, Tailwind v4, TypeScript, deployed on Vercel's free Hobby tier.
- **DNS:** apex + `www` → Vercel via GoDaddy DNS (A record + CNAME). No subdomains.
- **Pages:** Home, About, Content (Twitch/YouTube auto-pull + manual TikTok/Instagram embeds), Shop (flat-JSON listings, no checkout), Tools (native Stream Analyser page, see below, + live Discord bot status card), PTCG Binders (bookshelf redesign, see below), Contact (email + Discord webhook), 404.
- **Stream Analyser (`/projects/stream-analyser`, shipped):** native port of the formerly-separate StreamAnalyser Railway app (`github.com/SkylerMayday/skylerstreamanalyser`). Single-flow page (no tabs): username search → channel overview (followers/schedule/description-analysis/discoverability/community-protection, no subs/bits — those are broadcaster-token-only and have no public equivalent) → VOD picker → analysis (title rating, benchmark, bitrate, clip count, AI feedback/metrics) → Studio (chat-spike + audio-peak clip detection). No login, no local install — anything that required either was cut (OAuth, subs/bits cards, upload-recording/ffmpeg instructions, Settings tab, Stream History, Pre-Stream Checklist). Full spec: [docs/stream-analyser-port-spec.md](docs/stream-analyser-port-spec.md).
  - **Audio pipeline is new architecture, not a port of the old code.** Twitch has migrated VOD delivery from MPEG-TS to fragmented MP4 (CMAF) since the old app's TS-demux code was written — verified live that the old `demuxTStoADTS()` byte parser is broken against real VODs today. The new approach: fetch the HLS init segment (`init-0.mp4`) + a numbered fragment, concatenate the raw bytes server-side (CORS blocks direct browser fetch from Twitch's CDN), stream back — the browser's `decodeAudioData` decodes the concatenated fMP4 directly. No demuxing needed. `app/api/stream-analyser/audio-proxy/route.ts` + `app/api/stream-analyser/playlist-proxy/route.ts` handle the CORS-bypass leg; `lib/stream-analyser/audio-clip-detection.ts` (RMS energy windowing, echo autocorrelation, loudness/clipping stats) is the largely-unchanged analysis layer that operates on whatever `AudioBuffer` it's handed, regardless of how the bytes arrived.
  - Reuses the site's existing `lib/twitch.ts` app-access-token pattern (extended, not duplicated) and `lib/rate-limit.ts` fixed-window limiter — now applied to the new Claude relay (`app/api/stream-analyser/claude/route.ts`) and both proxy routes (the old Railway app left its proxy routes completely unrated-limited).
  - The old Railway app is kept running (not deleted) until Skyler confirms the native page works for him in a real browser — see `gaps.md` and `handoff.md` for what's still owed before retirement.
- **PTCG Binders:** `/ptcg-binders` is an overview page (overall completion %, changelog feed, then two bookshelves — see "Second bookshelf" below). Each section is its own browsable "binder" at `/ptcg-binders/[binderSlug]/[sectionSlug]` — a paginated 3×3 card viewer. Data fetched server-side from the existing `SkylerMayday/binders-pokedex-binder` GitHub repo (`binder.json`/`changelog.json`) — **this site has zero write access to that data; it is strictly read-only.** The publish pipeline (binder.json/changelog.json schema) is owned entirely by a separate project, `PokedexBinderV2` (`D:\Claude Projects\PokedexBinderV2`, the Android app) — untouched by this repo. The bookshelf visual design (see "Bookshelf redesign" below) went through several iterations based on direct owner feedback.
  - **Card zoom (shipped 2026-07-10, commit `6d0f12a` + scroll-lock fix `7849da2`):** tapping a filled `CardSlot` opens `CardZoomModal`, a full-screen lightbox (portaled to `document.body`) showing the same `imageUrl` already loaded for the grid thumbnail, larger — no new image fetch, no higher-res source. Closes via button, backdrop click, or Esc; traps and restores focus; respects `prefers-reduced-motion`. Ships with a body scroll-lock (`scrollbar-gutter: stable` on `html` avoids the layout-shift the first version's author skipped scroll-lock to avoid — the correct fix was to solve the shift, not skip the lock) plus an `overscroll-behavior`/`touchmove` guard for iOS scroll-chaining. Spec: `docs/ptcg-card-zoom-spec.md` (P0 only — no caption, no in-modal prev/next, no swipe-to-close, no higher-res fetch; deliberately not parked as a fast-follow).
  - **Mobile swipe-to-turn-page (shipped 2026-07-10, commit `12e569a`):** swipe left/right on the grid turns the page, additive alongside the existing arrow buttons/dropdown (not a replacement — those stay as the accessible fallback). Spec: the "Mobile Swipe Navigation" addendum in `docs/ptcg-binders-redesign-spec.md`.
  - **Second bookshelf for non-Pokédex binders (shipped 2026-07-11, commit `4599693`, `dev-team-pipeline`, verdict SHIP).** Prior to this, every binder in `binder.json` rendered flattened into one shared shelf (`BinderBookcase`'s original design). Skyler asked for a second, currently-empty shelf reserved for future binders (Connecting Art, Personal Collection), with "Card History" grouped into the *existing* Pokédex shelf specifically when it eventually publishes. Architecture: `lib/binders.ts`'s new `partitionBindersByShelf()` splits `binderFile.binders` by an explicit allowlist (`SHELF_1_BINDER_IDS = ["pokedex", "cardHistory"]`) — anything not on the list, including binder ids that don't exist yet, lands on shelf 2 automatically with **no code change needed** when PokedexBinderV2 eventually publishes real data there. `BinderBookcase` gained `heading`/`emptyMessage` props and a full-chrome empty-cabinet branch (cap/shelf/plinth all render; the shelf interior shows a centered message instead of spines when empty) rather than growing internal multi-shelf grouping logic — `page.tsx` renders it twice as sibling sections instead. The page's completion bar now filters to the Pokédex binder specifically (`findBinderBySlug`), not all binders combined — Card History and future Personal Collection entries aren't dex-completion-shaped data (no `dexNumber`/1025 total), so mixing them into one percentage would be meaningless. Caught via live measurement, not assumed, documented in place. **Known, deliberately-scoped-out P2, not an oversight:** once shelf 2 actually gets populated, it will inherit shelf 1's base `min-height` tiers (sized for 13 Pokédex sections) as a floor until re-measured against real content — can't be pre-solved without fabricating placeholder data, which the spec explicitly forbids.
  - **Lock icon + language/remarks display (shipped 2026-07-16, commit `afec1bb`, `write-spec` → `dev-team-pipeline`, verdict SHIP).** Read-only consumer of three additive `binder.json` fields `PokedexBinderV2` started publishing (commit `7921b82`): `language` (default `"EN"`), `remarks` (nullable free text), `isLocked` (boolean, default `false`) — only ever non-default on Pokédex/Unown slots. `BinderSlot`/`RawBinderSlot` in `lib/binders.ts` gained the three fields, defaulted in `normalizeSlot` (a guarded language default coerces blank/whitespace strings to `"EN"` too, not just `null`/`undefined` — prevents an empty badge from rendering on malformed data). `CardSlot` shows a small translucent lock-icon overlay (top-right, `pointer-events-none`, decorative only — doesn't block the click-to-zoom) on filled+locked tiles, mirroring `ShopCard`'s existing sold-badge convention. `CardZoomModal` shows a top-left language `Badge` (only when not `"EN"`) and a remarks text panel below the image (only when non-empty after trim); `isLocked` is deliberately NOT threaded into the modal — it's a grid-tile-only visual marker. Spec: `docs/ptcg-card-lock-language-remarks-spec.md`. Known non-blocking gap (Reviewer-flagged): if the grid thumbnail image itself 404s, the tile falls through to the empty-slot placeholder branch, losing the lock icon and click-to-zoom along with the image — pre-existing fallback behavior, not introduced by this feature.
  - **This connects to a real, still-open cross-project gap.** PokedexBinderV2's own multi-binder system (schema v7, "Connecting Art"/"Personal Collection"/"Card History" nav drawer) has been built and committed since 2026-07-06 but was **never installed on-device, never verified, and never published**. Worse: reading that project's actual `PublishRepository.kt` directly (2026-07-11) confirmed Connecting Art and Personal Collection aren't even wired into the app's own publish function yet — only `pokedex` and `cardHistory` (and `unown`, deferred) have real, working publish paths. See PokedexBinderV2's own `handoff.md` for the full finding. This website's second-shelf work is deliberately decoupled from and does not block on any of that — it's ready to receive real data the moment it exists, on either side's own timeline.
- **Shop listings:** flat JSON file (`data/shop-listings.json`), zod-validated (fails the build loudly on malformed data instead of silently dropping records), edited via git, redeploys on push. Validation logic lives in an exported `parseShopListings(data: unknown)` (`lib/shop.ts`, extracted 2026-07-16 for unit-testability); `loadShopListings()` is a thin delegate that reads the real JSON import and calls it — same contract as before, now with 10 unit tests covering the schema's failure branches.
- **Contact:** `/api/contact` route — validates input (length caps, email format, honeypot), rate-limited (10 req/IP/hour, in-memory), delivers via Resend email (authoritative — response depends on this leg succeeding) with a Discord webhook firing independently as a notification-only ping (never blocks a successful email send). Validation logic lives in `lib/contact-validation.ts` (extracted from the route 2026-07-16, 24 unit tests) rather than inline in `route.ts` — **not a style choice, a hard constraint:** Next's App Router type-checks `route.ts` files and rejects exporting anything beyond the recognized handler/config names, so any logic that needs direct unit-test access has to live outside the route file. Apply the same extraction pattern to any future route handler that needs testable internals.
- **Discord bot status card:** `/tools` shows live online/offline status for the "SkylerMayday" Discord bot via Discord's public Server Widget API (no bot token/secret needed) — gracefully degrades to an "unavailable" state if the widget is disabled/unreachable.
- **Twitch/YouTube:** server-side only (`lib/twitch.ts`, `lib/youtube.ts`), credentials in Vercel env vars, never client-exposed. Reuses StreamAnalyser's existing Twitch Developer app/Client ID.
- **Security headers:** CSP (scoped to actual browser-loaded origins only — Twitch/YouTube/Pokémon-TCG image CDNs, Discord CDN, TikTok/Instagram embed origins), X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, `X-Powered-By` disabled. Configured in `next.config.ts`.

## Bookshelf redesign — iteration history (worth knowing before touching `components/binders/*`)
The PTCG binders visual went through **eight rounds** of direct owner feedback:
1. **v1** — vertical color-block spines, thin plank strip. Rejected: "doesn't look like a proper bookshelf at all, binders too blocky."
2. **v2** — added book-detail layers (top cap, page-block, seams, label plate) and switched colors to side-by-side sub-binders. Book details improved close-up, but the shelf still didn't read as a shelf at normal viewing scale, and a real CSS bug left the cabinet side-walls invisible (`height: 100%` on a flex child of an auto-height parent resolves to 0).
3. **v3** — driven by three concrete instructions: (a) every spine must be one **fixed size** regardless of content (no height jitter), (b) revert colors to **v1's horizontal stacked bands**, not v2's side-by-side treatment, (c) rebuild the shelf as an actual **wood-textured container** (grain + gradient via `background-blend-mode`, thick `border-bottom`, shadow stack) — ported from real proven reference CSS in a *different* project (`D:\Claude Projects\PokedexBinderV2\web\pokedex-binder-site\styles.css`'s `.shelf` rule, which the owner explicitly said looked better than anything tried on this site). Also fixed spine **width** (was ballooning to ~200px on desktop via flex-basis fractions; fixed to ~104px to match real book proportions).
4. **v4 (touch-up)** — removed a literal box-frame border around the whole bookcase (read as a picture frame, not furniture) in favor of wood planks on the left/right edges only; rebuilt the per-row plank divider as a real 3-tone ledge (highlight + body + shadow) instead of a flat stripe, since a flat stripe blended into the wood grain and didn't read as a surface the books rest on; shortened "Generation N" labels to "Gen N" (display-only) so they fit the fixed spine width; pushed the book's cylindrical shading to more gradient stops per skeuomorphism best practice for a rounder read. **Rejected on live review**: "I want the binders… to look either like books or binders, but keep the colour scheme / design, just the shape."
5. **v5 (real CSS 3D, shipped 2026-07-10, commit `5b5ee5d`)** — the diagnosis that unlocked it: v1–v4 all *painted* 3D cues (top-cap sliver, cylindrical gradients, page-block strip, base shadow) onto a flat rectangle — the silhouette never changed, so the owner kept rejecting the shape. v5 builds actual geometry: each spine is a `preserve-3d` object back-tilted 6°, viewed from a per-Link raised eye (`.binder-scene`: `perspective` property + `perspective-origin: 50% -240px`), with a genuine `rotateX(90deg)` **top face** (card-page edges + cover-board strips derived from the frozen palette via `color-mix`), cover-edge ridges at `translateZ(2px)`, and a real elliptical contact shadow rendered *outside* the transform so it stays on the floor plane. The painted cues were deleted, not layered over. Frozen colors/bands/labels/gauge/wood shelf untouched. Two speculative flourishes were cut by their own pre-agreed cut lines after screenshot review: a leaning binder (read as physically unsupported) and metal rings on the top face (illegible at ~5.4:1 foreshortening).
6. **v6 "Open Carcase" — cabinet/shelf rebuild, spines untouched (shipped 2026-07-11, commit `582daea`, via `design-team-pipeline`, verdict SHIP).** After v5, the owner explicitly parked further hand-tuning on the *spine* geometry as not worth more investment, then separately asked to "redo the bookshelf, keep the binders/spines" — a request scoped to the container the spines sit in, not the spines themselves. New architecture, not another tuning pass on the existing shelf technique: a crown rail (new element, 12px, `--wood-frame` token) + retoned/widened side uprights (14px→20px) give the frame a tone visually distinct from the shelf interior without a box-frame border (avoids re-triggering v4's "picture frame" rejection — the new front-lip-vs-frame tone split is the actual evidence, confirmed by direct screenshot comparison). The shelf-board ledge was rebuilt from a flat 3-tone stripe into a 5-band motif (soft contact-shadow / hard highlight / body / hard underside-shadow / back-panel sliver) — this is what actually closed the long-standing "weak structural separation" complaint. A new low-alpha back-panel seam texture layer was added. Reviewer-flagged residual weakness: dark-mode frame/upright contrast is correct at the CSS level but hard to perceive by eye — root-caused to `--wood-frame`'s darkness floor (can't go darker without clipping the `--grain` texture to invisible). **Superseded by v8 — see below.**
7. **v7 "Cubby Grid" — attempted, rejected, fully abandoned (2026-07-11, `design-team-pipeline`, verdict NEEDS-CHANGES).** After seeing v6 live, the owner shared reference photos of a real cube-shelf bookcase and asked for "the structure" — read as individually bordered compartments (dividers on all four sides between spines, not just between rows). Built as real CSS Grid (`auto-fill`, no JS) with each spine wrapped in a new `.binder-cell` sharing the frame/interior color split at cell scale. Reviewer verdict: the grid mechanism itself was sound and not the problem, but two things failed — the divider between cells was too subtle to register at desktop's normal viewing scale (measured ~2:1 contrast, confirmed present on zoom, not confirmed by eye at a cold look), and 13 sections don't divide evenly into any column count, so the trailing partial row rendered as a bare, unstyled rectangle that read as broken UI, not intentional empty space. Owner's response when asked how to proceed on both fixes: **"Stop."** Uncommitted diff discarded, working tree reverted to v6. Full detail preserved in `.pipeline/archive-bookshelf-v7-cubby-grid-needs-changes/` in case the compartment-grid idea is ever revisited — it is not currently planned.
8. **v8 "Slim Carcase" — cabinet/shelf rebuild, replaces v6 entirely (shipped 2026-07-11, commit `e41c5f8`, via `design-team-pipeline`, verdict SHIP).** After v7's stop, the owner shared a new reference photo — a tall, narrow, single-column dark wood bookcase with four plain shelves, no vertical dividers at all — with the instruction: **"I want this structure. You decide the colour."** This meant abandoning v7's compartment-grid direction entirely (confirmed explicitly, not inferred) and returning to a single continuous shelf per tier, but rebuilt much more minimal than v6: cap/side-panels/shelf-boards all shrink from v6's 12-50px range down to a uniform 8px, all sharing **one continuous `--wood-body` tone** (no separate frame color at all — a stronger structural argument against re-triggering v4's "picture frame" rejection than v6's tone-split ever was, since there's no contrasting rectangle left to misread as decorative). A genuinely new element — a flared base/plinth, no precedent in v1-v7 — was added, with the one deliberate soft/blurred shadow in an otherwise all-hard-edge design (a floor-contact shadow is a physically different phenomenon than a material edge, and is treated differently on purpose). Corners went square, matching the reference and removing the `overflow:hidden` clip that would otherwise cut off the plinth's flare. **Color was explicitly delegated** ("you decide") — proposed a 3-token system where fill contrast stays a deliberately modest ~2:1 ambient cue and hard-edge `--wood-hi` highlight lines carry the actual legibility, tuned *stronger* in dark mode than light — a direct structural response to v6 and v7 both shipping contrast that measured fine on paper but didn't visually register. Skyler gave one direct mid-pipeline correction — "use a brighter dark colour" — applied to `--wood-recess` (moved from a near-black L≈5% first draft to L≈14%, close to v6's old `--wood-frame` tone) before implementation. CLS `min-height` constants dropped substantially (605/1151/1575px → 544/1098/1522px), dominated by the 50px front-lip shrinking to a 1px border. Reviewer-confirmed low-severity, non-blocking finding: the side panel's 1px inward highlight doesn't register at a cold glance (the panel itself does, via its own fill contrast — a separable, more important claim that holds fine) — cheap follow-up if wanted is 1px→2px, not attempted this session.

**CSS-3D top-face geometry rationale (v5's load-bearing decision):** the v5 brief originally specced per-item `perspective()` *inside the item's transform*. Stage-3 testing proved that construction geometrically incapable of ever showing the top face: the `perspective()` function puts the eye at the element's own transform-origin height, and from there a backward-extending `rotateX(90°)` top plane projects behind the spine at ANY tilt sign (confirmed experimentally at ±10° and by projection math). The fix — and the rule for any future 3D work here — is that **the eye must be above the object**: `perspective` as a *property* on the untransformed parent Link plus a raised `perspective-origin` (`--binder-eye`). Per-Link scenes (not one shared shelf-wide perspective) are deliberate: a shared vanishing point skews edge items and changes the read per wrapped row; per-item scenes keep every binder identical at any row position and any future section count. Tuning dials: `--binder-tilt`, `--binder-eye`, `--binder-depth` in `:root`.

**Coupled magic numbers — resolved for real in v6, no longer a sharp edge.** Through v5, the shelf's row-ledges were anchored to hand-computed repeating-gradient cycles (252px desktop / 212px mobile) hard-encoding `Link pt-3 (12px) + book height + row-gap` in prose comments — any change to those three values would silently desync the ledges from the binders' feet. v6 replaced the literals with `--binder-book-h`/`--binder-link-pt`/`--binder-row-gap`/`--binder-row-pitch` tokens (the last `calc()`-derived from the first three), so the cycle is computed, not hand-recomputed. Changing spine size/padding/row-gap now only requires updating the three source tokens — the pitch follows automatically.

**Lesson for future work here:** when the owner says a design "doesn't look right," get the actual rendered screenshot in front of yourself before assuming a fix worked — computed-style verification confirms code correctness, but only a real screenshot (and ideally the owner's own live-site look) confirms it actually *looks* right. Several rounds here had CSS that was technically correct but still failed visually until screenshots were actually inspected. v5 reinforced it from the other side: the screenshot-first tester was what caught the impossible-geometry spec bug that every mechanical check had passed.

**Automated visual regression exists now (2026-07-16, commit `abd654c`) for exactly this lesson — but only partially.** `e2e/bookshelf-visual.spec.ts` (`npm run test:visual`, Playwright) pixel-diffs the shared cap/shelf/plinth/wood-token chrome against 6 committed baselines, anchored on the second shelf's deterministic empty-cabinet state so it doesn't drift as Skyler's collection fills in. It will catch a regression in the shared shell the next time this file gets touched — the CSS-3D spine/top-face geometry above and the populated-row layout are NOT covered (no deterministic fixture for populated content exists), so the "get a real screenshot in front of yourself" discipline above still applies in full to any change touching `BinderSectionSpine` or the per-item 3D transform. See `gaps.md` for the open gap.

## Why the big decisions were made
- **Next.js + Vercel over a second Railway service** — Railway's Hobby plan shares a $5/mo credit across services (already used by StreamAnalyser); this site is mostly static with occasional API routes, fitting Vercel's free serverless model without new recurring cost.
- **PTCG binders as a native page, not a subdomain/proxy** — unified bookcase UI with one URL per section underneath. Old GitHub Pages viewer's page-flip-viewer feature spec was marked superseded once this site's native redesign covered the same ground (see PokedexBinderV2's `handoff.md`) — that viewer stays live in maintenance-only mode pending eventual retirement, not touched further.
- **StreamAnalyser absorbed into this site, not linked as a separate product** — done. The login-free native port shipped at `/projects/stream-analyser`, so the standalone Railway app (`github.com/SkylerMayday/skylerstreamanalyser`) is retired and `D:\Claude Projects\StreamAnalyser` is an empty shell. Stream Analyser is a page of this site now, not a tool this site links to.
- **No e-commerce checkout in v1** — showcase/contact-to-buy flow only, avoiding PCI/payment complexity.
- **Shop listings via flat JSON + git, not an admin form or CMS** — zero new auth surface/backend, consistent with the binder publish schema's own pattern.
- **Contact form is email (authoritative) + Discord webhook (notification-only, never blocking)** — matches the existing Discord embed pattern used elsewhere and keeps a single source of truth for delivery success.
- **Security headers use `'unsafe-inline'` for script/style-src, not a nonce-based CSP** — Next.js App Router's inline hydration script and the TikTok/Instagram embeds' own uncontrollable inline scripts would both break under a strict nonce policy; this was a deliberate, justified choice, not an oversight.
- **Auto-push standing instruction** — for this repo specifically, always push immediately after committing without asking first; Skyler needs to see the live deployed result to give feedback (his own instruction, see `~/.claude/rules/lessons/auto-push-live-deploy-projects.md`).
- **Playwright over jsdom/React Testing Library for the bookshelf's visual coverage (2026-07-16, still true for the bookshelf specifically)** — the repo's actual recurring bug pattern across 8 bookshelf redesign iterations was CSS/layout defects that were technically correct but "didn't look right until screenshots were actually inspected" (see the bookshelf lesson above). jsdom has no real layout/paint engine and structurally cannot catch that class of bug; Playwright's pixel-diff `toHaveScreenshot()` targets it directly.
- **Component-level testing (jsdom + React Testing Library) — added 2026-08-05, standing rule going forward.** The 2026-07-16 decision above only ever justified *not building it for the bookshelf's own risk class* — it was never a blanket "component logic doesn't need testing" call, and got read that way by omission. Reversed at Skyler's explicit request after `CardSlot`'s empty/filled/broken-image branching shipped a real logic bug (lock icon + click-to-zoom silently disappearing on a 404'd thumbnail) that neither `lib/*.test.ts` (pure functions only) nor Playwright (bookshelf chrome only) could have caught — state transitions, conditional rendering, event handlers, and a11y attributes are exactly what jsdom+RTL is for and exactly what neither existing test layer covers. **Standing rule now**: any new or touched interactive component with real logic (state, conditionals, event handlers — not a static presentational component) gets a jsdom+RTL test as part of shipping it. Wired as a separate vitest environment so `lib/*.test.ts` stays on the fast node environment, not forced into jsdom.
- **Visual-regression baselines target live production, not local dev** — this repo's local Node fetch hits a TLS-interception error (`UNABLE_TO_VERIFY_LEAF_SIGNATURE`, likely a corporate/AV proxy on this machine) on any external host, which blocks server-side data fetching in local dev entirely (see `handoff.md`'s failed-attempts history). Testing against `skylermayday.com` directly sidesteps it and matches what past sessions already did successfully via `gstack browse`. No CI exists for this repo yet, so there's no "deploy race" risk today (a stale baseline just fails loudly on next manual run) — but if CI ever gets wired up here, this design needs revisiting first.

**Card-zoom modal touch-listener rationale (load-bearing, don't "simplify" this):** the mobile swipe-page-turn listener in `BinderPageViewer.tsx` is attached via native `element.addEventListener("touchstart"/"touchend", ...)` on the grid `<div>`, deliberately NOT via React's synthetic `onTouchStart`/`onTouchEnd` JSX props. Native listeners follow the real DOM tree; `CardZoomModal`'s backdrop is portaled to `document.body`, outside the grid's DOM subtree, so a native grid listener structurally cannot fire for a touch that lands on an open zoom modal. React synthetic handlers propagate along the *React* tree instead (grid → CardSlot → portal), which would have let a swipe on the modal leak through and turn the page behind it. If this ever gets refactored to synthetic props "for consistency," that collision bug comes back.

## Conventions / sharp edges
- Two separate but related repos: `SkylerMaydaySite` (this directory — specs/docs/handoff) and `skylermayday-site` (the actual Next.js code, capital/lowercase matters on the filesystem). Don't confuse them.
- PTCG binder data model: one `Binder` (`id: "pokedex"`) containing multiple `BinderSection`s (Generation I-IX, Regional Variants, Alternate Forms, Mega Evolutions, VMax). The *website* treats each section as its own browsable "binder" for display purposes only — this is a presentation-layer choice, not a change to the underlying publish schema. If you ever need to change what data gets published, that's a different project (`PokedexBinderV2`), not this one.
- `sectionSpineColors.ts` hex values are intentionally frozen across all bookshelf redesign iterations — real game-title branding colors per generation (e.g. Gen I = red/green/blue/yellow). Don't casually "improve" these without an explicit ask.
- When testing locally, always track the exact dev-server PID before killing it — `taskkill /F /IM node.exe` kills every Node process on the machine (including unrelated tools like Stream Deck's own Node runtime) and has caused real problems once already this project.
- GoDaddy's Website Builder / Domain Forwarding features can silently compete with Vercel's DNS if not fully disconnected — this caused a real TLS certificate conflict early on (resolved). If cert warnings ever recur, check GoDaddy's account for a re-attached Website Builder product before assuming it's a Vercel/DNS problem.
